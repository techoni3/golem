# Typed control-plane shell

`apps/control-plane` is the foreground-only Fastify 5 composition shell for the future typed control plane. Its public `server.ts`/`index.ts` facades are deliberately thin: `auth.ts`, `routes.ts`, `ws-replay.ts`, `compatibility.ts`, and `lifecycle.ts` respectively own transport authentication, Zod/Fastify validation, replay policy, legacy/static compatibility, and process composition. It does not import legacy dashboard state or replace runtime/tracker routes.

The shell binds only to `127.0.0.1` and requires an explicit bearer token, compared in constant time. Bearer CLI/MCP clients are not browser clients: their mutations and typed sockets do not need an `Origin`. The same bounded, expiring HttpOnly/`SameSite=Strict` browser-session authority instead admits a typed socket only when its cookie is valid and `Origin` exactly equals the request protocol, Host, and port; browser mutations additionally require a constant-time CSRF token. Missing, malformed, expired, cross-host, cross-scheme, and cross-port browser session attempts are rejected. Unsafe Host is always rejected. Fastify and the deterministic OpenAPI document share strict `ApiErrorV1` response schemas; invalid input, revision regressions, and invalid handler output map to that stable GOL-26 envelope.

GOL-81 adds only browser-work routes: four typed, cursor-bounded projection streams on `/api/v1/projections/{stream}`, ticket detail, ticket-bound asset, and `/api/v1/browser/work/commands`. The shared projection path keeps its legacy runtime schema/client, while the browser four use a concrete discriminated response and a separate concrete WebSocket frame union for snapshots, allowlisted invalidations, and resync; generic JSON frames remain legacy-only. Those routes resolve cookies only (never bearer), use CSRF for writes, expose strict allowlists of opaque IDs/status/time/revision, and hand one typed envelope to GOL-79. GOL-80 provides project revision, invalidation, and replay; routes own no stores, CAS/idempotency, or policy state, while the GOL-79 receipt preserves the original safe command revision for replay. Dispatch remains typed unsupported until GOL-82. Viewer sessions can read, but resolver policy rejects mutation.

The typed v1 surfaces are liveness/readiness, metadata, canonical runtime live/history/diagnostic read models at `/api/v1/runtime/{live,history,diagnostics}`, browser bootstrap/echo, OpenAPI, and authenticated `/api/v1/ws`. Runtime projections read the owner’s typed SQLite rows: live excludes terminal generations, history retains lifecycle and provenance, endpoint health/readiness/capability facts remain separate from actor activity, observations are read-only, and diagnostic values are recursively redacted and bounded. Each page carries a monotonic resource revision, bounded cursor/limit pagination, explicit explanation facts, and a legacy-drift status without merging legacy state. Its injected replay port defaults to a bounded 1–256-entry window: transport sequence is monotonic and distinct from the exactly supplied canonical resource revision (a regression is rejected). GOL-80 drains only the persistence owner’s committed opaque invalidation rows after commit; it scopes by project and policy before a socket frame is formed, and each scoped stream has an independent bounded cursor. Frames carry snapshot, opaque delta, or explicit `cursor_gap`/`cursor_compacted`/`instance_changed`/`policy_changed` resync reasons; restart, compaction, and policy gaps never synthesize a delta, and the HTTP projection revision is canonical. The existing headerless `/ws` remains a separate legacy dashboard contract: an injected compatibility source supplies top-level `{type:"snapshot"}` and delta frames, and legacy `ping` receives top-level `pong`. `/api/health` and `/api/meta` return concrete legacy-shaped discovery JSON. The root `dashboard/dist/` remains the authoritative `golem dashboard` static artifact and snapshot route; the typed shell is generated separately under `dashboard/dist/control-plane/` and is served only by the foreground control plane. `golem dashboard --help` remains a non-starting compatibility entrypoint; no runtime/tracker handler is reimplemented.

`apps/control-plane/generated/openapi.json` is the deterministic artifact from the shell’s Zod route schema. `tools/openapi-codegen` consumes that artifact using only its isolated TypeScript 5/OpenAPI Typescript toolchain and writes `packages/api-client/src/generated/openapi.ts`; `packages/api-client` is the runtime `openapi-fetch` consumer. `npm run api:generate` regenerates and `npm run api:check` proves freshness. Production code never imports the tool workspace.

At startup the foreground process acquires `GOLEM_HOME/control-plane/control-plane.lock` containing PID plus nonce. Status distinguishes absent, active, stale, and malformed ownership; stale dead-PID recovery is guarded, while release unlinks only an unchanged matching owner record. SIGINT/SIGTERM drain WS clients, close Fastify, then release the lock. LaunchAgent install/update write a mode-0600 temp file, fsync and close it, rename it, then fsync the containing directory; a prior plist is durably backed up and restored if the injected post-rename/pre-directory-fsync interruption boundary fails. Install/start/status/stop/update/rollback accept an injected argv-based `launchctl` boundary and use absolute foreground paths. `RunAtLoad` is false: neither postinstall nor installation auto-starts a user service.

The one `control-plane-auth-ws-lifecycle` J6 scenario runs compiled foreground and invalid-response child processes under temporary `GOLEM_HOME` roots. It verifies generated-client bearer mutation without Origin, cookie flags and cross-origin/CSRF denial, browser-session typed socket acceptance without exposing a bearer to dashboard JavaScript, all cookie rejection cases (including deterministic clock expiry), strict request/output/409 envelopes, a typed socket connected before live broadcast plus valid/compacted/restart replay, headerless legacy snapshot/ping/delta compatibility, and the shipped headless dashboard store ingesting that snapshot/delta. It also proves nonce-safe crash recovery, durable interrupted LaunchAgent swap rollback, redaction, signal cleanup, and temporary-root removal. It reports `UNMET` if a sandbox prevents a real loopback listener.
