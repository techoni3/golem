# Typed control-plane shell

`apps/control-plane` is the foreground-only Fastify 5 composition shell for the future typed control plane. Its public `server.ts`/`index.ts` facades are deliberately thin: `auth.ts`, `routes.ts`, `ws-replay.ts`, `compatibility.ts`, and `lifecycle.ts` respectively own transport authentication, Zod/Fastify validation, replay policy, legacy/static compatibility, and process composition. It does not import legacy dashboard state or replace runtime/tracker routes.

The shell binds only to `127.0.0.1` and requires an explicit bearer token, compared in constant time. Bearer clients are not browser clients: their mutations do not need an `Origin`. Browser mutations instead require the bounded, expiring HttpOnly/`SameSite=Strict` session cookie, matching loopback Origin, and constant-time CSRF token comparison. Unsafe Host is always rejected. Fastify has registered request/response JSON schemas; invalid input and invalid handler output map to the stable GOL-26 `ApiErrorV1` envelope.

The only typed v1 surfaces are liveness/readiness, metadata, empty injected projection ports, browser bootstrap/echo, OpenAPI, and `/ws`. The injected replay port defaults to a bounded 1–256-entry window; frames carry the GOL-26 instance id, monotonic sequence/revision, and snapshot, delta, or explicit `cursor_gap`/`cursor_compacted`/`instance_changed` resync reason. A changed instance id never resumes a stale cursor. `/api/health` and `/api/meta` return the concrete legacy-shaped discovery JSON, static requests serve `dashboard/dist`, and `golem dashboard --help` remains a non-starting compatibility entrypoint; no runtime/tracker handler is reimplemented.

`apps/control-plane/generated/openapi.json` is the deterministic artifact from the shell’s Zod route schema. `tools/openapi-codegen` consumes that artifact using only its isolated TypeScript 5/OpenAPI Typescript toolchain and writes `packages/api-client/src/generated/openapi.ts`; `packages/api-client` is the runtime `openapi-fetch` consumer. `npm run api:generate` regenerates and `npm run api:check` proves freshness. Production code never imports the tool workspace.

At startup the foreground process acquires `GOLEM_HOME/control-plane/control-plane.lock` containing PID plus nonce. Status distinguishes absent, active, stale, and malformed ownership; stale dead-PID recovery is guarded, while release unlinks only an unchanged matching owner record. SIGINT/SIGTERM drain WS clients, close Fastify, then release the lock. LaunchAgent install/update use temp-file rename plus backup rollback; install/start/status/stop/update/rollback accept an injected argv-based `launchctl` boundary and use absolute foreground paths. `RunAtLoad` is false: neither postinstall nor installation auto-starts a user service.

The one `control-plane-auth-ws-lifecycle` J6 scenario runs compiled foreground and invalid-response child processes under temporary `GOLEM_HOME` roots. It verifies generated-client bearer mutation without Origin, cookie flags and cross-origin/CSRF denial, request/output envelopes, valid/compacted/restart replay, concrete compatibility/static fresh browser shell, nonce-safe crash recovery, explicit atomic LaunchAgent verbs, redaction, signal cleanup, and temporary-root removal. It reports `UNMET` if a sandbox prevents a real loopback listener.
