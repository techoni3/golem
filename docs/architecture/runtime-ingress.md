# Durable runtime ingress

GOL-34 keeps runtime producers outside SQLite. A producer validates a GOL-26 `RuntimeSignalV1` and writes only beneath its temporary or service-owned `GOLEM_HOME/inbox`: a private temporary file is fsynced, atomically published without clobbering an existing event id, and the directory is fsynced. The authenticated control-plane `POST /api/v1/runtime/events` is the equivalent ingress; it receives only the spool port, never a persistence handle.

The one service owner claims `pending` files by rename into lease-stamped `processing` files. Only expired claims can be reclaimed. Each retry carries bounded attempt/backoff metadata; a poison envelope becomes a no-clobber quarantine record with a redacted diagnostic after its final attempt. It validates schema/version and size before dispatching to an explicitly registered, pure materializer handler. A short persistence transaction records the raw source event/dedupe key, producer watermark, canonical mutation, explanation diagnostic, and optional `runtime_outbox` record. Only after that commit does it archive the source. Archive and quarantine use no-clobber publication: a committed-but-unarchived byte-identical source is deduplicated and removed, while conflicting bytes remain inspectable outside the original archive.

`runtime_outbox` remains an at-least-once boundary. The drainer leases bounded claims, gives the stable outbox id to its destination as the idempotency key, and acks only after that destination returns. Ack/failure CAS losses are explicit result counters, never silent successes. A service-down or consumer-crash failure receives bounded retry/backoff semantics; exhausted records retain observable permanent-failure metadata. Persisted failure diagnostics are redacted and bounded. The service-owned scheduler runs both materialization and outbox draining with no overlapping tick, bounded shutdown, and payload-free retry/permanent/last-success health facts.

The compact real J3 `materializer-crash-matrix` is the regression proof: 100 independent native filesystem producers plus duplicate ids, active/expired leases, bounded poison quarantine, no-clobber archive, child-process crash positions, restart dedupe, stale watermarks, and an independent SQLite consumer crash/replay with exact outbox transitions. The separate J1 `dashboard-down-inbox-replay` proves producers can write while no dashboard/control-plane process exists, then a fresh real control-plane start replays every envelope without opening SQLite from producer processes.
