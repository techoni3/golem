Architecture field guide · 11 July 2026

Two harnesses.One accountable control plane.

Golem v5.0.16 gives Claude Code and OpenCode one durable operating surface: normalized session identity, a dashboard-owned tracker, addressed delivery, quiet observation, and evidence-backed work completion. The adapters differ at the runtime edge; authority and coordination converge in the middle.

Superseded historical snapshot

This guide predates GOL-132 and retains the passive-coordination design as historical context. It is not the current implementation contract. Read docs/substrate-events.md for the active event-ledger and session_notify model.

Claude Code OpenCode SDK bridge Channel protocol Dashboard Tracker lifecycle Durable registries

Claude Code

Native hooks and a per-session channel child normalize a Claude session into the shared registries and tracker API.

OpenCode

A local shim maps runtime events, owns the SDK bridge, and injects trusted per-call identity for shared MCP tools.

Control plane

The dashboard is the tracker database writer and the place where envelope facts, browser updates, and lifecycle evidence meet.

01 · shared mental model

Converge at facts, not at implementation

An adapter establishes a session and a last-mile delivery method. It does not become a second tracker. The same logical actor can be seen through a native session source, a Golem registry row, a reachable channel, and—in OpenCode—a bridge to the SDK. Those are deliberately separate facts.

Identitylogical session records
Reachabilitylive channel endpoint
InjectionOpenCode bridge only
Work truthdashboard-owned SQLite
Authority boundary

Hooks and the OpenCode shim write registry and journal facts. The dashboard owns tracker.db. Channel MCP tools use dashboard HTTP; agents do not write the tracker database directly.

02 · deployment is part of the system

Trace the bytes that a session can actually load

The substrate is the authored plugin source. Each harness has a distinct path from source to active runtime. A clean source checkout is not, by itself, evidence that a live session is running those bytes.

Claude Code: rendered bundle → installed cache

Source. substrate/ and the channel package are planned by the Claude Code adapter. Render. golem sync --target cc writes the workspace plugin render; golem sync --target cc-marketplace creates the local marketplace entry pointing at it.

Activation. Add the workspace marketplace, install or update golem@golem-workspace, then start a new session or run /reload-plugins. A pushed channel event additionally requires a session launched as a channel consumer; merely loading the tools is not consumer activation.

OpenCode: rendered files + managed configuration

Source. The OpenCode adapter renders substrate agents, skills, and instruction blocks. Render. Enable harnesses.opencode.enabled in ~/.golem/config.json, then run golem sync --target opencode.

Activation. The sync preserves user configuration while merging Golem’s MCP entry, skill path, and file-URL shim into opencode.jsonc; it validates with opencode debug config when the binary is available. Start an OpenCode runtime after that configuration is present. Because its MCP and shim point at the checkout, moving the checkout requires another sync.

03 · sessions, channels, bridges

Address a logical actor without guessing

A session row says who an actor is. A channel row says whether a dashboard message can reach it. An OpenCode bridge says which SDK-bound process can inject a model turn. Separating those facts lets resume, reload, and sibling-session cases remain explicit.

OpenCode lifecycle boundary

The shim tracks top-level sessions, keeps child sessions from fabricating dispatch endpoints, and treats retry as busy. It writes registration and bridge state without waiting on shell hooks, so a hook failure does not stall the host runtime.

Claude Code discovery boundary

Native session discovery prioritizes the Claude CLI view, then native registry files, while Golem rows contribute metadata. For resumed sessions, the parent session file preserves the logical identity that channels and tracker actors share.

04 · durable work delivery

A brief is a tracked conversation, not a best-effort push

A dispatch creates an addressable message envelope. Delivery acceptance records an opportunity to show the brief; it does not prove the model picked it up. The recipient acknowledges the correlated envelope, can reply through its stored route, and produces lifecycle evidence while doing the work.

01IntentImmediate dispatch durably assigns before delivery. Idle delivery persists a queue row and its envelope.
02OpportunityA live channel accepts an addressed brief. Offline or unreachable queued work remains pending rather than being burned.
03PickupThe stored target acknowledges the correlated envelope; spoofed or mismatched callers are rejected.
04ReplyA reply child uses the durable sender route. Its delivery is independently recorded.
05CompletionEligible terminal phase evidence from the acting recipient stamps the delivered envelope complete.

Unacknowledged is bounded

After a delivery opportunity reaches its acknowledgement deadline, the drainer creates one acknowledgement reminder. If it remains unacknowledged after that reminder’s escalation point, it creates one escalation through the stored reply route.

No automatic reassignment

Reminder and escalation add facts; they do not select a replacement owner. Ticket ownership changes only through an explicit dispatch or reassignment action, preserving an auditable accountability chain.

05 · superseded model-free observation

Historical passive design (retired)

This section records the pre-GOL-132 design only. Passive observation, subscriptions, and next-turn context injection were retired; current sessions use durable reports plus active session_notify messages.

Allowed facts

Canonical tracker events project phase, assignment, blocker state, and result. Ordinary comments, activity telemetry, and mirrored spec-tree rows do not become prompt context.

Slot and cursor

One slot per recipient, ticket, and category coalesces baseline to latest value. A per-session cursor preserves a claimed batch for replay if the lease is not settled.

Quiet interest

Manual subscriptions can make a recipient eligible for passive facts. Subscription digests are disabled by default, so a subscription does not create an unsolicited model turn.

06 · derived communication health

Make attention visible without inventing a second state machine

Communication health is read from envelope facts: assignment, queueing, delivery attempt or opportunity, acknowledgement, reminder, escalation, reply, completion, and dismissal. The API returns a display-safe factual timeline rather than raw message payloads; the dashboard derives severity at read time.

Green

No active delivery failure or unacknowledged deadline is degrading health. Queued work is counted but does not by itself make communication unhealthy.

Amber

An active envelope is awaiting acknowledgement or has received its reminder. The timeline retains the original delivery and deadline facts.

Red / Needs You

Delivery failure or escalation is red. “Needs You” is narrower: it identifies an active, unacknowledged escalation rather than every red item.

Freshness model

The browser starts from a snapshot and reacts to WebSocket deltas. Communication surfaces use revision-driven refetches after relevant fact changes; they do not run a polling loop. The dashboard remains the single source for the derived health calculation.

07 · work, evidence, closure

Delivery starts a work journey; it does not replace proof

The tracker phase machine governs the work lifecycle. A dispatched builder still reads the assigned work, follows its role lane, records mechanical evidence, and leaves a closing brief. Delivery facts explain communication; ticket phases and comments explain whether the requested work was actually completed.

Lifecycle authority

Tracker phase is the workflow source of truth and board state is derived. Phase transitions, ticket events, and comments are persisted by the dashboard, then rebroadcast to browser clients and eligible passive observers.

Completion evidence

When an acting non-human recipient reaches an eligible terminal phase on a delivered ticket, the envelope can be stamped complete. That links communication to a tracked result without treating transport acceptance as proof of implementation.

ROLEPick up the right lane

Load the assigned work and apply the manager, planner, builder, or explorer contract before altering lifecycle state.

EVIDENCERun the claimed checks

Mechanical output—not an assertion—supports a review, built, verified, or done transition.

CLOSELeave the four-part brief

State what changed, acceptance evidence, human test steps, and any deferred work or limitations.

OBSERVEKeep coordination calm

Subscribe when quiet interest is enough; use a durable actionable envelope when another session must be asked to act.

08 · operating checklist

Load the intended bytes, then verify the intended route

Use this release sequence after a change to substrate, channel code, hooks, or the OpenCode shim. It distinguishes render correctness from harness activation and from live delivery readiness.

Claude Code release path

  1. Set the intended root package version, then run golem sync --target cc and golem sync --target cc-marketplace.
  2. Use the workspace marketplace and update golem@golem-workspace so Claude’s installed cache receives the rendered plugin.
  3. Start a new session or run /reload-plugins.
  4. For pushed briefs, launch the target as a channel consumer and confirm its channel registration is reachable.

OpenCode release path

  1. Enable harnesses.opencode.enabled in ~/.golem/config.json.
  2. Run golem sync --target opencode; retain a successful managed opencode.jsonc merge and its validation when the binary is available.
  3. Confirm the configured checkout paths still point to this repository; re-sync after moving it.
  4. Start OpenCode, then confirm its top-level session has both a bridge row and a reachable channel row before dispatching work.
