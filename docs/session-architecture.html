Architecture field guide | 10 July 2026

Two harnesses.One durable control plane.

OpenCode and Claude Code begin with different identities, lifecycle APIs, and last-mile delivery mechanisms. Golem translates both into the same session registry, channel protocol, dashboard state, durable message envelopes, tracker phases, and evidence-backed closing brief.

OpenCode runtimeClaude Code runtimeOpenCode bridgeShared channelDashboardTracker lifecycleDurable registries

OpenCode

An in-process shim owns lifecycle translation and the SDK bridge. A sibling MCP child owns the dashboard-facing channel.

Claude Code

Native hooks own lifecycle data. A per-session MCP child emits Claude channel notifications directly.

Convergence

Both become session IDs, channel endpoints, tracker actors, envelope recipients, comments, phases, and browser updates.

01 | shared mental model

One control plane, two adapters

The harness adapters answer two questions: who is this session? and how can a brief become a model turn? Everything after those answers is shared.

Load-bearing invariant

The dashboard owns tracker.db. Hooks and shims own registration files. Agents never write SQLite directly; tracker MCP tools are HTTP clients for dashboard REST.

02 | authority boundaries

A file is not a channel, and a channel is not a session

Each artifact establishes one fact. A session row describes identity and state. A channel row describes a reachable endpoint. An OpenCode bridge row describes access to the SDK-bound runtime.

03 | OpenCode journey A

Startup: two processes race, then converge

OpenCode loads a local shim plugin and launches the shared MCP channel as separate cooperating components. The shim can publish a bridge only after an active session exists. The channel may start first, so bridge-file observation closes the ordering gap.

Resume seeding

The shim asks OpenCode for session.list() and session.status(). It seeds active top-level sessions, or at most one recent fallback, so persistent history does not become phantom live agents.

05 | OpenCode journey C

The channel routes; the bridge injects

The shared channel is SDK-agnostic. It receives the durable dispatch, identifies the target sibling, and forwards to the bridge. Only the bridge can turn the envelope into an OpenCode model turn.

Sibling identity and chat attribution

One OpenCode process may expose multiple top-level sessions through one MCP port. The shim injects __golem_session_id on each Golem tool call, so durable tracker writes and envelope acknowledgements remain recipient-validated. The process-wide /events broadcast cannot identify one sibling, however, so dashboard chat currently duplicates or misattributes sibling ack/respond events.

06 | Claude Code journey A

Runtime begins upstream of the session

Claude Code does not execute the checkout directly. Source is compiled into a workspace render, surfaced through a marketplace, installed into Claude's plugin cache, and only then loaded by a new session or plugin reload.

Operational activation

Hook or channel changes need render sync, plugin update when cache bytes differ, and a new session or /reload-plugins. Global instructions are written separately to ~/.claude/CLAUDE.md.

07 | Claude Code journey B

Startup: native identity, parallel hooks, direct channel

Claude Code supplies a native process registry and logical session ID. SessionStart hooks register metadata and context while the MCP child independently binds the channel endpoint.

Resume identity

The parent file ~/.claude/sessions/<pid>.json is preferred over a transient environment ID. A new PID/port can still represent the same logical actor.

Safe replacement

The new MCP child replaces stale channel rows. Cleanup removes by its own PID so an old child cannot delete its successor.

08 | Claude Code journey C

Every real turn fans into lifecycle evidence

Claude invokes command hooks around prompts and selected tools. The local journal is written first. Dashboard event delivery is best effort and backed by a per-session spool.

Coverage boundary

The current manifest does not match every possible tool or tool failure. Glob, Grep, WebFetch, WebSearch, plugin MCP tools and PostToolUseFailure are not all represented.

09 | Claude Code journey D

The channel is the last mile

Claude Code needs no SDK bridge. The dashboard-facing channel converts POST /brief directly into notifications/claude/channel. A correlated ack is the durable proof that the intended session processed it.

Launch contract

Actionable pushes require claude --dangerously-load-development-channels plugin:golem@golem-workspace (the golemc path). A live channel PID proves the endpoint exists, not that the model consumes notifications.

10 | shared control plane

Durable first, network second

Dispatch never depends on a successful push to become auditable. Assignment and the message envelope are written before the network call. Queueing changes when delivery is attempted, not where truth lives.

Dashboard poll

Native session reconciliation runs every three seconds and emits native-sessions-update.

Channel SSE

One /events consumer per session maps ack/respond/consult into dashboard chat.

Browser WS

Snapshot plus deltas; reconnect receives a fresh snapshot. Durable ticket/session state reconverges, but in-memory chat does not survive dashboard restart.

11 | shared completion contract

A closing brief is a tracker artifact

Neither a model answer, a channel response, nor SessionEnd completes the canonical implementation journey. The builder writes a four-part tracker comment and then uses the validated transition endpoint to move from building to built.

Enforcement reality

The operational contract requires all four sections, but the transition endpoint accepts either a comment matching /closing\s+brief/i or the explicit closingBrief:true override. Legacy PATCH, generic ticket_update, and move paths can also change state/phase without calling the artifact validator. The skill and verification contract is therefore stricter than every currently exposed write path.

12 | upstream and downstream impact

Where a change propagates

The most expensive mistakes come from changing one plane while reasoning about another. This matrix shows which runtime must restart, which registries change, and where users see the consequence.

OpenCode shim

shims/opencode/index.js

Upstream: OpenCode plugin API and SDK. Downstream: events, bridge rows, session state, passive context and caller identity. New/restarted OpenCode process required.

Claude hooks

substrate/hooks/* -> render -> cache

Upstream: hook manifest and compiler. Downstream: registries, journals, context and status. Sync alone is not activation; update plus reload/new session may be required.

Shared channel

mcp/channel/index.js

Upstream: host MCP transport and parent identity. Downstream: both harnesses' tools, HTTP delivery, SSE, consults and routing. Running children keep loaded bytes.

Registry schema

sessions | bridges | channels | projects

Upstream: hook/shim writers. Downstream: discovery, context, liveness, project identity, dispatchability and consult lookup.

Dashboard state

native-sessions | state | index | chat

Upstream: registries and events. Downstream: card latency, reachability, queue decisions, SSE consumers and browser WS. Polling changes affect both harnesses.

Tracker and phases

tracker-db | phase-machine | role skills

Upstream: tools and dashboard actions. Downstream: assignment, comments, passive deltas, gates, verification, completion and board state.

Known edges

Claude reachability does not prove channel consumption. OpenCode sibling SSE events are process-wide and currently duplicate or misattribute dashboard chat. Legacy ticket mutation paths can bypass phase artifact validation. The four-part brief is stricter in skills than in the database regex. Installed Claude cache bytes can lag a clean workspace render.
