Philosophical Shift — Can spec = Slack?

Assessment

Goal: stay in spec, not terminal. Feasibility: yes, with 5 holes closed. The stores already exist (ticket + comments + dispatch envelopes); what is missing is default routing, presence, and rail ergonomics.

What “holes” would bite us

Risks → Mitigations
Dispatch vs chat intent • the expensive one

Same words for “note to self” vs “send to agent”. Today everything queues as undispatched — safe but noisy. Fix: composer has two distinct actions: Comment (save) vs Comment + Dispatch (save + push). Add toggle “Auto-dispatch to assignee when live” (persisted per spec). When on, “Comment” = dispatched.

Agent long paste • instruction, not just UI

Agents put 400-line reports in comments because instructions permit it. Fix: tighten tracker + building + exploring: “Reports > 20 lines → child doc. Comment = 3-line summary + link + dispatch pointer.” Clamp handles overflow visually but policy prevents the write.

Nested dispatch ambiguity

A reply to an addressed thread should not re-open every ancestor. Rule: reply that comes from the dispatched session and matches parent_id or same block_id marks only that dispatch addressed. UI shows thread status aggregated from leaf dispatches.

Colored rails mystery

Left border = author color (TA_AUTHORS map → soft/mid/bd vars). Thick orange edge = .is-active (selected). Red/orange rails you saw = orphan (lost anchor) → var(--status-blocked). Fix: add legend, tooltips, and switch “active” to accent-underline not orange-border to avoid overload.

Performance at 100+ comments

Rail virtualizes naturally via clamp + filter (Show resolved). Beyond 80, add pagination or “Load older” rather than infinite DOM.

Direction A — Slack Threads

Recommended

Metaphor: Each anchored block is a thread root. Replies indent with a vertical connector, can collapse as a group, each reply is its own card with its own dispatch state and anchor-jump. Composer is pinned to the rail bottom (“Message #spec-GOL-277”). Feels like Slack/Notion comments.

  • Best for long-running back-and-forth (the requested Slack use)
  • Nested UX: Replies OUTSIDE parent card, slight indent (14px), left connector line, “Hide 3 replies” toggle per thread
  • Attribution: Avatar (initials) + name + role chip + time; author color as subtle top accent, not full rail
  • Actions: Top-right icon row: ⧉ Anchor ⤢ Expand · bottom row: Reply · Edit · Dispatch (primary) · Resolve (toggle)
  • Long content: 7-line clamp + gradient fade; “View full → doc” when over 30 lines
Trade-off: more DOM nodes than today, but clearer threading at 20+ replies. Collapse keeps scan cost low.

Direction B — Linear / Clean

Minimal

Metaphor: Minimalist Linear.app / Figma comment pins. Ultra-clean cards, tiny avatars, muted borders, actions appear on hover. Good for specs with many small notes, not long threads.

  • Best for tidy specs where each comment is a short decision
  • Nested UX: Flat list, reply is a slightly muted inline block under parent with “Show thread” disclosure
  • Attribution: Small dot + name, no big avatar; author color only on dot
  • Actions: Hover toolbar (Reply, Resolve, ···) — very quiet
  • Trade-off: Beautiful at low volume; can feel cramped at 30+ comments, harder to see dispatch state

Direction C — GitHub Timeline

Audit-heavy

Metaphor: GitHub issue timeline. Each comment is an event on a vertical line; state changes (dispatched → addressed → resolved) render as timeline dots. Replies are nested but also appear on the line. Strong for auditability, weak for chat flow.

  • Best for review-heavy specs where every comment's state matters
  • Nested UX: Timeline branch per thread; replies sit on a spur
  • Attribution: Avatar left of line, timestamp right of dot
  • Actions: Per-card, plus timeline-level filters: “Show unresolved only”, “Show dispatches”
  • Trade-off: Great audit trail, but the vertical line consumes gutter and threading feels heavier than Slack

Recommendation: Direction A (Slack Threads) — matches the stated goal (“full-fledge Slack-like collaboration”) while staying within the existing data model (parent_id + dispatch_state + block_id). Pair it with two cross-cutting fixes independent of direction: explicit Anchor/Expand buttons + avatar/legend + long-paste instruction tightening. Build C’s timeline dots later as an optional filter, not the default rail.
