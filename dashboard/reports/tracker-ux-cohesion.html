01 — Scope

Eight tickets, one browser, no bundler

The dashboard renders JSX at runtime through @babel/standalone from https://unpkg.com. There's no node_modules in the browser, no Vite, no webpack. Every new feature must work with that constraint — which is why this build looks more like an editorial publication than a typical feature stream.

Why no bundler

The dashboard ships as a single npm start with index.html loading React + Babel-standalone from CDN and JSX components transforming at runtime. This is the v4 architecture decision (TKT-0013 onwards). It means any browser-side dependency must be loadable as a script tag or via the import-map pattern documented in §B · React-via-esm.

02 — Stream architecture

One ledger, two surfaces, five phases

The tracker is the source of truth. Each ticket is one piece of work; the dashboard server holds the SQLite DB and broadcasts deltas. The frontend reads from window.Store (in-memory mirror), renders via React, and never polls.

Why a ledger + a store, not just one

The SQLite DB is the durable source of truth (audit trail, move history, auto-archive). The in-memory window.Store is the read-side cache that React components subscribe to. Every mutation flows server → DB → WS delta → store. The frontend never writes to the DB directly; every mutation is a fetch to the API.

03 — Phase A

Drawer brownfield: stop the rail from scrolling with the body

Two tickets closed the most-cited paper cut: the comments rail and the FAB rode the body's scroll position. Both are now portaled to the drawer root and pinned with position: absolute against the drawer — so they stay glued to the right edge regardless of how long the ticket body is.

Acceptance — TKT-0108

Open any long ticket, scroll the body 500px down. #anno-rail and #anno-fab have unchanged getBoundingClientRect().top. Verified across all three drawer widths (90/50/30%) with a headless-Chrome probe.

04 — Phase B

Board usability: drag, search, color

Three tickets — an inspection memo, the drag implementation, and the color/search layer. The library choice (@dnd-kit) was decided in the memo before any code was written; the implementation thread resolved the two-React trap; the search and color thread made the board scannable.

TKT-0102 · library memo

Inspection of native HTML5 DnD vs react-dnd vs @dnd-kit vs custom pointer events. Recommendation: @dnd-kit/core v6.3.1 + @dnd-kit/sortable. Bundle: ~24KB gzip. Maintenance: 18 months without npm release; the maintainers are pivoting to @dnd-kit/dom. Mitigation: hooks are confined to TrackerCard + TicketColumns — easy to swap later.

TKT-0103 · drag impl

DndContext wraps the board. useDraggable on each card with 6px activation distance (so click-to-open still works). useDroppable on each column. onDragEnd cross-column → PATCH state; same-column → optimistic reorder (rank persistence is Phase C's job). DragOverlay shows a tilted ghost.

Console: 0 errors. Headless Chrome probe: drag works, server confirms state.
TKT-0104 · search + color

Client-side useMemo filter on id/title/kind/priority/assignee/project, debounced 80ms. Color rules: 5 kind stripes; 4 priority tints; pulsing glow for questions; opacity 0.62 for Done, 0.5 + grayscale for Archived.

05 — Phase B · infra

The two-React trap, and how we got out of it

Adding @dnd-kit to the dashboard ran into React's most-cited browser gotcha: the UMD React (loaded via <script>) and the ESM React (served by esm.sh) are different module instances. The DnD hook's useMemo ran on one React; my component's useState ran on the other. Hooks threw Cannot read properties of null — classic two-React anti-pattern.

The pattern that ships

Rule of thumb for v4: browser-side deps must load via esm.sh with an import map. UMD scripts stay only for non-React dependencies that don't share state. If a new dep needs bundler-style features, vendor a pre-built ESM/UMD file under dashboard/web/vendor/. Don't reintroduce UMD React. The full pattern is in the in-session memory note project_dashboard_react_esm.md.

06 — Phase C

Archive lifecycle: schema, move, sweep

The P1 ticket of the stream. Adds four lifecycle columns, a single move endpoint that writes state + rank + lifecycle stamps atomically, and a 14-day sweep that archives Done tickets with an audit event.

Move endpoint

Rank computed as midpoint of neighbours. Both null → max(rank of target state) + 1000. Same-state reorder emits a rank_change event instead of state_change. State + rank + state_changed_at land in one UPDATE; lifecycle stamps attached as conditional SQL.

Probe: TKT-0002 → in_progress → state=in_progress, rank=114000, state_changed_at=NOW
14-day sweep

autoArchiveDone() queries done tickets where done_at < cutoff. Each archived ticket gets a state update + an auto_archived event with the original done_at preserved. Triggered on startup (setImmediate) + every 6 hours (setInterval with unref()). Manual trigger: POST /api/tickets/auto-archive/sweep.

Probe: TKT-0001 done_at=now-15d → sweep → archived, archived_at=NOW, event row written
07 — Phase D

Image paste: GitHub-style for the new-ticket composer

v1 ships on the New Ticket composer only. Drawer edit mode and comment composer are explicitly out of scope. The asset pipeline is content-addressed (sha256 → filename) so the same image uploaded twice deduplicates for free.

08 — Phase E

Recency: composite signal + 7/30/90-day sidebar

The dashboard's sidebar used to order projects by directory mtime. That lies — a project that's just been rediscovered bumps to the top regardless of whether anything actually happened there. Now the signal is the max of four real-work indicators, and the sidebar groups by 7/30/90-day activeness with live sessions bubbling to the top of each bucket.

Composite signal

Each signal is wrapped in try/catch so one failure doesn't zero out the others. The git signal uses spawnSync('git', ['log', '-1', '--format=%ct'], { cwd, timeout: 1500 }) so a project with no git repo doesn't stall the rediscover.

test: maxTicketUpdatedAt('golem-1eba80') = 1782468368054 ms (matches MAX(updated_at))
7/30/90 buckets

Active ≤7d, Recent ≤30d, Stale ≤90d, Archived >90d. Within each bucket: live sessions first, then last_activity_at desc. Empty buckets don't render their heading. The Projects nav counter shows the Active count specifically.

test: 13 projects → Active 7, Recent 3, Stale 3, Archived 0

Protocol

For every ticket, the worker (in this case the CEO running inline because the volume was small enough): (1) make the edit, (2) restart the dashboard, (3) run node scripts/jsx-check.mjs, (4) run PORT=7420 scripts/check.sh, (5) drive a headless Chrome probe via playwright-core against http://127.0.0.1:7420/?bust=<ts> to bypass CDN caches, (6) attach a probe report (measured counts, dimensions, network codes) to the ticket thread as the verify step. No worker subagents were used for this stream because the user explicitly requested headless-Chrome verification as we go.

11 — Glossary

One-liners

TermDefinition
babel-standaloneThe CDN-served Babel that transforms <script type="text/babel"> tags at runtime, so the dashboard needs no build step.
esm.shThe CDN that serves npm packages as ESM. We use it to load React and @dnd-kit into the browser without a bundler.
import mapA <script type="importmap"> block that resolves bare specifiers ("react") to URLs ("https://esm.sh/react@18.3.1"). The native browser feature that makes esm.sh work.
portalReactDOM.createPortal(node, target) renders a React subtree into a DOM node outside the parent's hierarchy. Used to hoist the rail out of the scrolling body.
two-React trapLoading React twice (UMD + ESM) gives two module instances. Hooks called on one can't see state set on the other. Fix: load React once.
content-addressed storageFiles named by the sha256 of their bytes (<hash>.<ext>). Uploading the same image twice writes zero extra bytes; serving by hash is safe to cache forever.
rankAn ordering column on tickets; midpoint of neighbours. Allows manual reorder without rewriting every row. Backs the in-column DnD reorder and any future "pinned to top" UX.
state machinetodo → in_progress → blocked → review → done → archived (auto). The four new lifecycle columns carry the timestamps.
composite last_activity_atMax of: live session heartbeat, ticket updated_at, journal mtime, git commit time. Replaces the workspace-mtime signal that lied about activity.
WS deltaA small JSON message broadcast on the WebSocket when a single row changes. The client store merges deltas; the server re-sends the full snapshot if the client misses too many.
